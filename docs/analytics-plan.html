3Visitor ID and the day

Stored in the browser

localStorage['mnaisp-analytics'] = {
  vid:    "Xq3fP0…" ,   // 16 random bytes, base64url, 22 chars
  day:    "2026-11-17", // site day, from the server
  sent:   [pageKey…],   // pages already sent today
  opened: [pageKey…]    // pages already opened on today
}

Shared by all tabs, so a visitor is counted once per day across tabs.

The server is the clock

  • Every track response returns { day } in the site time zone.
  • If it differs from the stored day, the browser makes a new ID and empties sent / opened.
  • The visitor's own clock and time zone never matter.
  • The server only accepts IDs matching ^[A-Za-z0-9_-]{22}$.
Edge cases. If localStorage is blocked, the ID lives in memory for that page only, so the visitor may count again on the next page (rare, accepted). If the site time zone changes later, days already stored stay as they were.

The visit that last wrote in this chat. A chat continued the next day credits the new day's visit.

Per-page funnel. Started, asked and talked go to the page where the visitor sent the first message of the day (first_msg_page). A visitor who opened on Home but wrote on Pricing counts as started on Pricing only.

Median from a histogram

Bucket upper bounds in seconds: 10 · 30 · 60 · 120 · 180 · 300 · 600 · 900 · 1800 · 3600 · ∞. The median is the bucket holding the middle visitor, with an interpolated value shown as "≈ 1 m 20 s". Today and old ranges use the same method, so numbers never jump when details are deleted. The average stays exact (seconds ÷ openers).

6Browser

widget/analytics.ts (in the loader, every page)

  • Tiny, no React, no imports from chat modules.
  • Queue: flushes after 1 s with fetch keepalive; uses sendBeacon on pagehide or when the tab is hidden.
  • View: when the page is idle (requestIdleCallback, fallback 2 s), if the page isn't in sent yet.
  • Open (floating): in setOpen(true) on a button, label or notification click. The automatic closed mount is not an open. Once per page per day.
  • Open (shortcode): the first pointerdown or keydown inside .mnaisp-chat-inline.
  • Skip when navigator.webdriver is set, analytics is off, or track: false.
  • Shares the ID with the chat bundle through window.mnaispAnalytics = { vid(), time(s) }.

widget/useActiveTime.ts (chat bundle)

  • Counts while the panel is open (inline: in viewport), the tab is visible, and there was activity in the last 60 s.
  • Activity: typing, pointer down or move, scrolling in the chat, or a new message arriving (answer start/end, team reply, event).
  • Ticks once per second in memory. Sends the seconds on close, tab hidden, pagehide, and every 2 min while counting.
  • Never runs in the admin Preview, which doesn't use useChat.

7Rollup and purge (cron)

New daily event mnaisp_analytics_daily, scheduled from admin_init like the conversation purge.

1 · Rollup (idempotent)

days = every day < today with detail rows
       AND (no daily row yet
            OR day ≥ today − 2)   ← late time / replies
for each day:
  REPLACE INTO daily  (site row + one row per page)
  FROM visits / pages

2 · Purge (retention_days > 0)

cutoff = today − retention_days   (only totalled days)
loop:
  DELETE FROM pages  WHERE day < cutoff LIMIT 5000
  DELETE FROM visits WHERE day < cutoff LIMIT 5000
  both < 5000   → done
  time > 20 s   → single event in 120 s, stop
Each DELETE commits on its own (autocommit, no surrounding transaction), so locks stay short. If retention is 0, nothing is deleted, but the rollup still runs to keep reports fast.

10Privacy

Privacy-policy text

New paragraph: an anonymous one-day ID in the browser; which chat pages were visited; whether the chat was opened or used; time spent. No IP, no message text. Details kept N days.

No personal data

Analytics tables hold no user ID and no IP, so no GDPR exporter or eraser is needed.

Paths only

No domain, no query strings, no #, because query strings can hold emails or tokens.

12Review questions (all answered 17 Nov 2026)

  1. Per-page funnel. AnsweredAlternative chosen: started = first message of the day sent on that page; asked / talked go to that same page. Each started visitor counts on one page. Needs only visits.first_msg_page and the pageUrl that /chat/ask already sends.
  2. Charts. AnsweredOwn small SVG components, no chart library.
  3. Approximate median. AnsweredTaken from the time buckets and shown with "≈" for every range. The average stays exact.
  4. Time flush every 2 min. AnsweredSend every 2 min while counting, plus on close, tab hidden and page close. A crash loses at most 2 min.
  5. Store device now. AnsweredStored in visits.device, and the site's daily row keeps per-device counts (devices JSON), so the later device split works for old days too. No device UI yet.
  6. On by default. AnsweredOn for new installs and for existing sites after the update.
  7. Settings place. AnsweredSettings tab: own card AnalyticsSettingsCard after the widget card, with its own Save. The Analytics tab links to it when analytics is off.
  8. Endpoint cost. AnsweredNormal REST endpoint. A lighter endpoint only later, if a big site needs it.

13Built: deviations from the plan

17 Nov 2026 · commits A0 5632580, A1 0d55a7b, A2 f4c3ad1, A3 8d96a82, A4 b488340, A5 privacy text.

WhatBuilt as
Visitor ID rotationThe browser computes the site day itself from analytics.tzOffset (site time zone offset, in the widget config) and makes a new ID before sending on a new day. The server's {day} only corrects the stored day (same ID), so one day never mixes two IDs.
Track request bodyForm-encoded (events[0][t]=…), not JSON: sendBeacon can't send a JSON content type reliably. Same body for fetch keepalive.
Track response offAlso for bots and excluded team members (not only analytics off): the browser stops sending from that page.
Asked vs talkedThe funnel shows "Asked for a person: N · talked to a person: M" without a "not answered" number: a team member can also reply in chats where nobody asked, so asked − talked would be wrong.
Time counts for openers onlySeconds of visitors without an open are left out of totals and averages.
Shortcode timeCounted only after the visitor's first interaction with the inline chat (being on screen alone is not using the chat).
Open records the viewAn open also marks the page as reported, so no separate view is sent for it.
Columnstime_buckets and devices are TEXT (not VARCHAR(255)) so big sites never cut the JSON. Device '' is stored as unknown in devices.
Tab placeAnalytics tab sits after Live chat.
Not testedThe purge time budget + follow-up event path (needs a backlog that takes over 20 s); batches and the loop were tested with 24,000 rows.

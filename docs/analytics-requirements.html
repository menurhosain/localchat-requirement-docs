Chatbot Analytics: Requirements

Requirements only, 17 Nov 2026. How it will be built is planned later. Source: docs/analytics-requirements.md

Show the site owner how visitors use the chatbot: how many people see it, open it, start a chat and end up talking to a person, how long they stay, and on which page they first opened it.

1Which pages count

Counted
Pages where the chatbot widget loads: the floating button or the [mnaisp_chat] shortcode. The tracking code lives inside the widget loader.
Not counted
Pages without the widget. This is not a general site analytics tool. Admin preview and Playground never count.
Page cache
Many sites serve cached HTML (WP Rocket, LiteSpeed, Cloudflare). PHP does not run for those visits, so counting must happen in the visitor's browser.

2The funnel (P0)

All steps are counted per day: how many came today, opened the chat, started a conversation, talked to a person. A range (e.g. last 7 days) adds up the days. Each step shows its count, % of the step before, and % of all visitors. Example numbers:

3Definitions

Each number needs one exact meaning, so the numbers never contradict each other.

TermMeaning
Unique visitorOne browser on one device, counted once per day however many pages it visits (5 pages = 1 visitor). The same browser on another day counts again (Monday + Tuesday = 2). A range total is the sum of the daily counts. Anonymous: no name, no IP, no fingerprinting. Page views are not counted.
Opened chatbotThe visitor opened the panel themselves (button or launcher label). Automatic re-open, e.g. a reload during a live chat, is not a new open. Shortcode chat (always visible): first click or typing inside it.
Started conversationSent at least one message: typed question, suggested-question click, or message to the team.
Asked for a personThe chat has a human-request event (requested / requested_offline).
Talked to a personA team member sent at least one reply in that chat. Take-over without a reply does not count.
Time on chatbotTime the panel was open and the tab visible and the visitor not idle (60 s without activity).
First-open pageThe page URL where the visitor opened the chatbot for the first time that day.

  • Share of first opens = this page's first opens ÷ all first opens in the range (62 ÷ 180 = 34%): where chatbot use starts.
  • Open rate = opens on this page ÷ unique visitors on this page (62 ÷ 240 = 26%): how often visitors of this page open the chat.
  • Sorted by first opens, top 20, with "show all".
  • Clicking a page shows the funnel for that page only: visitors on it → opened on it → started there (first message of the day sent on it) → asked / talked (credited to the same page). Each visitor who started counts on one page only.
  • URLs stored without query strings by default (privacy).

6Nice to have (P1, later)

  • Compare with the previous period (+12% opens)
  • Device split: desktop / mobile / tablet
  • CSV export
  • Separate per-page funnel screen
  • Click a number to see those chats in Conversations
  • Answered vs "I don't know" rate, top unanswered questions (E3)

7Who is excluded

  • Logged-in team members who can use Live chat (edit_others_posts). Not counted by default; a setting can include them.
  • Admin Style preview and Playground.
  • Known bots and crawlers.
  • Not excluded: Do Not Track / Global Privacy Control visitors. Both signals are ignored; everyone is counted.

8Privacy

Never stored

  • IP address (same rule as the conversation log)
  • Message text: analytics stores only that something happened
  • Query strings in URLs (may hold emails, tokens, order IDs)

Controls

  • Anonymous random visitor ID only
  • Own on/off switch, separate from recording
  • Detail rows: 90 days by default, days changeable or deletion off
  • Daily totals kept forever
  • Daily WP-Cron cleanup in batches, like conversations
  • Privacy-policy text, like the conversation log
  • Counts without waiting for cookie consent (anonymous one-day ID)

9Quality requirements

  • No slowdown. Tracking never blocks page load or the chat. Small requests, batched or sent with sendBeacon when the page closes.
  • Silent failure. A tracking error never breaks the widget.
  • Bounded DB growth. On busy sites, old detail rows are rolled up into daily totals.
  • Consistent numbers. Each funnel step is never bigger than the step before it.
  • Fast screen. 90 days on a busy site loads in under 1 s.
  • Access. Admins only. Editors keep seeing only Live chat.
  • WWC branch. Works there too; only the plugin name differs.

10Decisions (all answered 17 Nov 2026)

  1. Unique visitor across days. AnsweredUnique per day. Same browser Monday and Tuesday = 2. Range totals = sum of days. A daily anonymous ID is enough.
  2. Consent. AnsweredCount anyway, no waiting for cookie consent: the ID is anonymous and lasts one day. Owners who need consent can turn analytics off.
  3. Shortcode chat. AnsweredCounts as opened on the first click or typing inside it. Scrolling into view does not count.
  4. First-open page. AnsweredFirst open of the day (follows from question 1).
  5. Idle time. Answered60 s without activity (see section 4).
  6. Talked to a person. AnsweredOnly when a team member sent at least one reply. Take-over without a reply does not count.
  7. Team members. AnsweredExcluded (not counted) by default; a setting can include them.
  8. Retention. AnsweredDetail rows deleted after 90 days by default; setting to change the days or turn deletion off (small sites can keep everything). Daily totals kept forever. Deletion = daily WP-Cron job, like conversations.
  9. Free vs Pro. AnsweredAll analytics is Free, including the P1 extras.
  10. Recording off. AnsweredAnalytics keeps counting (own switch). "Asked for a person" and "Talked to a person" simply show 0, no extra note.
  11. Do Not Track / GPC. AnsweredIgnore both, count everyone.

11Not in scope

  • General web analytics: referrers, countries, bounce rate, pages without the widget.
  • Sending events to Google Analytics / GA4 (possible later as an option).
  • Per-visitor timelines or session recordings.
  • A/B tests of widget texts.

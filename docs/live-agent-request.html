Asking for a live agent

A visitor can ask for a person ("live agent", "can I talk to a human?") instead of the AI. The request goes to the team in the Live chat tab, the visitor gets an honest reply, and the AI keeps helping until someone takes over.

1The problem

Live chat takeover (D5) only starts when a team member happens to notice a chat. A visitor had no way to ask for a person: "live agent" was just another question.

Do you have any used equipment available at this time
Yes, our used equipment listings include a FARR Gold Series GS6… For current availability, please call 800.282.3878. [1]
live agent
I apologize, but I'm unable to determine the answer… search best match 0.55 passed the gate, AI found nothing
Could you transfer me to a live agent
I apologize, but I'm unable to determine the answer… same again
Why it failed. The request went through search, weak hits passed the gate (min_score 0.5), and the AI had nothing to say about it, so it used the "I don't know" text.

3The AI marker

Works like the "I don't know" text: the prompt tells the AI to reply with an exact text, and the server looks for it.

- If the visitor asks to talk to a person (a live agent, a human, someone from the team), reply with
  exactly [[HANDOFF]] and nothing else. Never translate it. If they only ask whether you are a person
  or a bot, say you are the AI assistant and ask if they want a team member to join; if they then say
  yes, reply with exactly [[HANDOFF]].

Detection

After the AI reply, AnswerService checks whether [[HANDOFF]] appears anywhere (case-insensitive; models sometimes add text around it). Then the result gets reason = handoff, and ChatController (via the AnswerResponder transform hook) calls request_person() and puts in the reply text.

Hiding it while streaming

MarkerFilter holds back any text that could be the start of the marker ([, [[HAND…) until the next piece shows what it is. Marker found → nothing more is shown; the final text replaces it. Citations like [1] are released as soon as the 1 arrives.

Streamed piecesVisitor seesMarker
"[[HAND", "OFF]]"nothingfound
"[", "[", "handoff", "]]"nothingfound
"Sure! ", "[[HANDOFF]]""Sure! " (then replaced)found

5cBrowser notifications

Notification API from the open page: no service worker, no push server. Shown only while the person isn't looking at the page (document.hidden or !document.hasFocus(): another tab or window in front, or minimized). A closed tab gets nothing.

Visitor (widget)

  • 🔔 / 🔕 button in the chat header; choice per browser (localStorage mnaisp-chat-notify)
  • After asking for a person: bar "Get a notification when the team replies… Turn on / No thanks" (a click, so the browser may ask)
  • On: AI answer, team reply, "{team} joined", the "no one joined" note
  • Click: focuses the page, opens the chat (mnaisp:open event → loader)
  • Site switch: Widget settings → "Let visitors turn on browser notifications" (default on)

Admin (Live chat tab)

  • "Turn on notifications" button; per browser (mnaisp-live-notify)
  • "<name> wants a person", "New message from <name>" (list sends lastVisitorMessageId / lastVisitorText)
  • Click: opens that chat; one notification per chat (tag)
Delay. AI answers are instant (same connection). Team replies and new visitor messages arrive by polling: up to 30 s in a background tab, up to ~60 s after Chrome throttles a tab hidden for 5+ minutes. Kept like this on purpose (user's call); faster = shorter hidden-tab polling + a Web Worker timer.

Found while testing: the admin app ran twice (WordPress loaded main-<hash>.js?ver=…, lazy chunks import it without ?ver → two modules, two React apps, double polling). Fixed in ViteAssets (74c329b): the built entry loads without ?ver.

  • Request = the moment LiveChatService::request_person() runs: phrase check, "yes" to the offer, or the AI marker. A repeat while the request is still open sends nothing.
  • Live chat off (recording off): counts as "no one online"; the email says the chat wasn't saved (no Live chat link).

  • Visitor: the "no one available" reply adds "We've let the team know by email." only when an email was queued.

How it leaves the server (never slows the chat)

1. Queue

  • During the chat request: AlertService builds an Alert; AlertDispatcher keeps it in memory (one per chat)
  • Hooks shutdown (priority 100)
→

2. Reply first

  • WordPress sends the reply
  • fastcgi_finish_request() (PHP-FPM) or litespeed_finish_request() closes the connection
→

3. Send

  • Every configured channel's send() (email: wp_mail()) in the same request: arrives right away

5eAlert channels (email now; Telegram, SMS, WhatsApp later)

One interface, different implementations (channel / strategy pattern). Deciding when and what is separate from how it is delivered, so a new network only implements the interface.

AlertService

  • Triggers (request, new chat), team online, limits
  • Builds an Alert
  • No channel-specific code
→

AlertDispatcher

  • Channel registry
  • Queue → after the reply / WP-Cron
  • Sends to every configured channel; one failing doesn't stop the others
→

AlertChannel

  • EmailChannel (now)
  • TelegramChannel, SmsChannel, WhatsAppChannel (later)

8Limits & next ideas

  • Phrases are English. Other languages rely on the AI marker, which needs the question to pass the search gate.
  • Custom prompts (e.g. the live Cooner site) need the [[HANDOFF]] rule pasted in; the Prompt screen warns.
  • Alerts: browser notifications (tab open) and email (no one online) are in. Slack / Telegram / SMS: later, with Smart Sales Alerts (D6).
  • Local testing of emails needs an SMTP plugin or a mail catcher (MailHog / Mailpit).
  • Next ideas: a "Talk to a person" button in the widget (D2/D3), tab-title count + sound for new requests, office hours.
